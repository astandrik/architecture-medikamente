# Проектирование решения

## Цель

C4 Context целевой MVP-архитектуры «Медикаменте» с механизмами Privacy by Design. MVP-сценарий: пациент сам записывается через Клиентский портал, а ресепшен видит запись и сопровождает приём.

Диаграмма решения: [c4-target-mvp.drawio](c4-target-mvp.drawio).

## Что меняется относительно As-Is

Целевая архитектура убирает основные риски As-Is состояния:

- вместо Excel-журнала и общего диска появляется контролируемый контур записи, `CRM / Patient Profile` и `Медицинский контур`;
- доступ к PII/PHI/FIN задаётся не фактом входа в домен, а идентификацией пользователя, RBAC/ABAC и политиками доступа по тегам;
- согласия, цели обработки и минимальный состав данных фиксируются в consent/privacy management;
- данные тегируются при сборе и передаче, например: `PII`, `PHI`, `FIN`, `RAW`, `PROCESSED`, `ANONYMIZED`, `GOLDEN_SOURCE`;
- доступ, экспорт и изменения пишутся в audit/SIEM;
- Data Lineage, владельцы данных и метаданные ведутся в каталоге данных;
- аналитика получает только размеченные, обработанные и обезличенные наборы.

## Элементы целевой архитектуры на диаграмме

| Элемент диаграммы | Назначение | Privacy by Design механизм |
|---|---|---|
| Целевая система «Медикаменте» MVP | Граница MVP вокруг основных сервисов | Показывает, где применяются сквозные механизмы Privacy by Design |
| Ядро MVP | Клиентский портал, Портал ресепшена, `CRM / Patient Profile`, запись, `Медицинский контур`, `Платежи / 1С / ККМ` и лабораторная интеграция | Минимизация PII/PHI/FIN в пользовательских и операционных сценариях |
| Базовый слой Privacy by Design | Active Directory/Keycloak, согласия, Data Minimization, тегирование и классификация, RBAC/ABAC, audit/SIEM, Apache Atlas/Data Lineage, шифрование и управление ключами | Применяет политики доступа, теги, аудит и ключи ко всем блокам MVP |
| Аналитический слой с Privacy by Design | Контролируемая загрузка → сырой слой с карантином → обработанные данные с тегами → обезличенные витрины/золотой источник → BI/ML/AI | Не выпускает сырые PHI в аналитику и отдаёт только размеченные данные |
| Пациент | Самостоятельная запись, свои данные, согласия | Privacy by default и сбор минимального набора данных |
| Ресепшен | Сопровождение записи без PHI | Доступ по роли и минимизация медицинских деталей |
| Бизнес-аналитик | BI/ML/AI без сырых PHI | Доступ только к `ANONYMIZED` и агрегированным наборам |

## Аналитический слой с Privacy by Design

Аналитический слой с Privacy by Design не работает напрямую с Excel-выгрузками, сканами или сырыми медицинскими данными. Поток строится так:

1. Контролируемая загрузка принимает события и выгрузки из `CRM / Patient Profile`, записи, `Медицинского контура`, `Платежи / 1С / ККМ` и `Лаборатории`.
2. Сырой слой с карантином изолирует исходные данные и запрещает прямой доступ аналитика к необработанным PHI.
3. Обработанный слой нормализует данные, сохраняет Data Lineage и применяет теги.
4. Обезличенные витрины и золотой источник используются для BI, ML, AI и отчётности.
